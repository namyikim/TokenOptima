# 지표 정의

## 입력 자료

Claude Code 대화 기록 `~/.claude/projects/<프로젝트>/<세션>.jsonl`. 쓰는 것은 세 가지다.

- **API 호출**: `assistant` 줄의 `message.usage`
  - `input_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, `output_tokens`
  - 스트리밍으로 같은 `message.id`가 여러 줄 나올 수 있어 id마다 한 번만 센다.
- **프롬프트**: 도구 결과가 아닌 `user` 줄. `<`로 시작하는 시스템 알림(`<task-notification>` 등)과 `isMeta` 줄은 뺀다.
- **도구 결과**: `user` 줄의 `tool_result`. 크기는 글자 수. 어떤 도구·명령이었는지는 앞선 `tool_use`에서 찾는다.

## 상대 비용

입력 1을 기준으로 한 Claude 공통 비율이다(`tokenoptima/pricing.py`).

| 종류 | 가중치 |
|---|---:|
| 입력 | 1 |
| 캐시 읽기 | 0.1 |
| 캐시 쓰기(5분) | 1.25 |
| 출력 | 5 |

1시간 캐시 쓰기는 실제로 2배이지만, 기록만으로는 구분이 안 되어 1.25로 계산한다(보수적).

## 대화 지표

| 지표 | 정의 |
|---|---|
| 맥락 크기 | 호출 한 번이 읽은 토큰 = 입력 + 캐시 읽기 + 캐시 쓰기 |
| 캐시 적중률 | 캐시 읽기 ÷ (입력 + 캐시 읽기 + 캐시 쓰기) |
| 프롬프트별 비용 | 그 프롬프트부터 다음 프롬프트 전까지의 호출 비용 합 ÷ 대화 비용 |
| 새 작업 요청 | 25자보다 긴 프롬프트. 25자 이하는 확인 답변("네", "A", "2")으로 본다 |

## 줄일 수 있었던 양 (보고서 맨 위 숫자)

- **토큰:** (입력 + 캐시 읽기) × "작업마다 새 대화" 절감률 + 자리를 비워 다시 쓴 캐시 토큰. 대화마다 계산해 합한다.
- **비율:** 위 값 ÷ 총 토큰(입력 + 캐시 읽기 + 캐시 쓰기 + 출력).
- **비용 기준:** 같은 계산을 상대 비용으로 한 값. 캐시 읽기가 싸서 토큰 기준보다 낮게 나온다.
- 새 대화에서 파일을 다시 읽는 비용을 빼지 않았으므로 **상한**이다.

## 낭비 패턴

### 여러 작업을 한 대화에서 계속 이어감

"작업마다 새 대화를 열었다면" 호출 한 번의 평균 맥락을 계산해 실제와 비교한다.

- 새 대화는 첫 호출의 맥락(시스템 프롬프트·도구 정의·CLAUDE.md)에서 시작한다고 본다.
- 그 작업 안에서 늘어난 만큼만 더한다.
- 새 대화에서 파일을 다시 읽는 비용은 넣지 않으므로 **절감의 상한**이다. 실제 절감은 이보다 작다.

### 오래 비운 뒤 캐시 만료

- 앞 호출과 **60분 이상** 떨어진 호출이 **5만 토큰 이상**을 캐시에 다시 쓰면 잡는다.
- 영향은 그 캐시 쓰기의 상대 비용 ÷ 대화 비용이다.

### 짧은 확인 답변의 왕복

짧은 답 뒤에 이어진 실제 작업은 낭비가 아니다. 그래서 **첫 호출**(커진 맥락을 다시 이어 받는 데 드는 고정비)만 센다.
한 대화에서 세 번 이상 되풀이될 때만 패턴으로 본다.

### 큰 도구 결과

1만 자가 넘는 도구 결과. 한 번 들어온 결과는 이후 모든 호출이 다시 읽는다.

## 알려진 한계

- **새 작업 경계가 글자 수로만 정해진다.** 긴 확인 답도 새 작업으로 잡힌다. 주제 변화 감지는 다음 단계 과제다.
- **결과(작업 성공 여부)를 보지 않는다.** 토큰을 많이 썼어도 한 번에 끝났다면 낭비가 아닐 수 있다.
- **Claude Code 기록만 읽는다.** claude.ai 웹 대화, 다른 도구의 기록은 아직 없다.
