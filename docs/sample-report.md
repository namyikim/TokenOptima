# 토큰 사용 분석 보고서 — 샘플(저장소 작성자)

기간: 2026-09-06 ~ 2026-09-28 · 대화 3개

토큰 수는 AI가 실제로 읽고 쓴 양이다. 비용 비율은 달러가 아니라 상대값(입력 1 · 캐시 읽기 0.1 · 캐시 쓰기 1.25 · 출력 5)으로 계산했다. 계산 방법은 `docs/metrics.md`.

## 1. 한눈에 보기

| | 토큰 | 비율 |
|---|---:|---:|
| **총 사용** | 약 1.78억 | 100% |
| **줄일 수 있었던 양 (최대)** | 약 1.32억 | **74%** |
| **꼭 필요했던 양** | 약 4,567만 | 26% |

가격 차이(캐시 읽기는 정가의 10% 등)를 반영한 **비용 기준으로는 약 62%**를 줄일 수 있었다.
'최대'인 이유: 새 대화에서 파일을 다시 읽는 비용을 빼지 않았다. 실제 절감은 이보다 작다(대략 절반 이상).

## 3. 무엇이 문제이고 어떻게 고치나

영향이 큰 순서다.

### 🔴 한 대화에 여러 작업을 계속 이어감

- **문제:** 질문할 때마다 그 대화의 앞부분 전체를 다시 읽는다. 대화가 길어질수록 질문 한 번이 비싸진다.
- **기록:** 대화 2개에 새 작업 요청이 62개 쌓였다. 가장 긴 대화는 약 5만 → 약 58만 토큰까지 커졌다. 이것만으로 총 토큰의 **74%**.
- **고치는 법:** 주제가 바뀌면 **새 대화**를 연다. 예: '구독 기능' 끝 → 새 대화에서 '탭 디자인'. 이어 가야 할 규칙은 CLAUDE.md에 적어 두면 새 대화에도 자동으로 들어간다.

### 🟠 짧은 확인 답이 많음 ("네", "A", "2")

- **문제:** 한 글자 답에도 긴 대화 전체를 다시 읽는다. 오가는 횟수만큼 비용이 붙는다.
- **기록:** 확인 왕복 61번. 다시 읽는 데만 비용의 **10%**.
- **고치는 법:** 요청할 때 결정을 미리 담는다. 예: '메인에도 구독 버튼 넣고, 테스트 통과하면 커밋·push까지 해줘'. AI가 선택지를 물을 것 같은 일은 원하는 쪽을 먼저 적는다.

### 🟡 큰 출력이 대화에 남음

- **문제:** 파일 전체 같은 큰 출력은 대화에 남아, 이후 모든 질문에서 다시 읽힌다.
- **기록:** 1만 자가 넘는 출력 6건, 합계 107k자. 대부분 AI가 스스로 실행한 명령의 출력이다.
- **고치는 법:** CLAUDE.md에 '큰 파일은 필요한 부분만 읽고, 출력은 짧게 받는다'를 적어 둔다. 코드 전체를 봐야 할 때만 한 번 출력하게 한다.

### 🟡 오래 쉬었다가 같은 긴 대화로 돌아옴

- **문제:** 쉬는 동안 할인(캐시)이 만료되어, 돌아온 첫 질문에서 대화 전체를 비싼 값으로 다시 저장한다.
- **기록:** 1번, 가장 긴 공백 80분. 약 30만 토큰을 다시 저장했다.
- **고치는 법:** 한 시간 넘게 쉬었다면 긴 대화를 이어가지 말고 새 대화로 시작한다.

### ⚪ 모든 일에 가장 무거운 설정

- **문제:** 간단한 일(`git pull`, 문구 수정)도 큰 모델로 하면 같은 일에 돈이 더 든다.
- **기록:** 쓴 모델 claude-opus-5, claude-opus-5-5.
- **고치는 법:** 간단한 일만 할 대화는 시작할 때 가벼운 모델이나 낮은 effort를 고른다. 대화 중간에 바꾸면 할인(캐시)이 깨지므로 시작할 때 정한다.

## 4. 잘하고 있는 것

- ✅ **할인(캐시) 적중률 99.4%** — 다시 읽는 내용의 대부분을 정가의 10%로 읽고 있다. 다만 이것은 **단가**가 싸다는 뜻이고, 읽는 **양**이 많으면 총액은 커진다(위 3절).
- ✅ **짧게 끝낸 대화 1개** — 한 가지 일을 새 대화에서 바로 끝냈다. 이렇게 쓰면 싸다.
